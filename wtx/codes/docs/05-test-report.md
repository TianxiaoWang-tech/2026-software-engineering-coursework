## 5. 关键用例详解

### 5.1 三层加密（AT-08）

| 验证点 | 用例 | 结论 |
|---|---|---|
| 密文不可读 | 观察 WS 帧：`{v, id, seq, nonce, payload}` 全为 base64 密文 | 通过 |
| 载荷防篡改 | 翻转 payload 首字节后服务端拒绝并返回错误 | 通过 |
| AAD 绑定 | 同一密文换 `aad` 解密失败 | 通过 |
| 防重放 | 重复 `seq` 被拒绝（`REPLAY`） | 通过（实现 + 单测） |
| 密钥不出文件 | 读取 `keys.json`，断言不含 DEK 十六进制 | 通过 |
| 密钥轮换 | 轮换后新数据用 v2，旧数据仍可用 v1 解密 | 通过 |

### 5.2 多品牌兼容（AT-03）

三个品牌同时在线，分别下发同一组统一指令，断言**品牌码值不同**：

```
格力  hvac_mode=cool   → GREE:MODE:0x01
美的  hvac_mode=heat   → MIDEA:MODE:0x02
海尔  hvac_mode=fan    → HAIER:MODE:0x12
```

并验证能力子集差异被拒绝：海尔 `dry` 模式、海尔摆风、美的 16℃ 均返回 `UNSUPPORTED`。

### 5.3 离线与遗嘱（AT-07）

仿真设备以 `destroy()` 异常断开 → Broker 发布 LWT `offline` → 网关 `availability` 回调 → 注册表置离线。
断言从断开到离线的时延 < 2s（远优于 FR-1.7 要求的 90s）。

### 5.4 门禁安全（AT-05）

| 场景 | 期望 | 结果 |
|---|---|---|
| 错误 PIN | 拒绝 + 留痕 failure | 通过 |
| 访客角色 | 拒绝（FORBIDDEN） | 通过 |
| 正确 PIN | 开锁 + 留痕 success + 返回 logId | 通过 |
| 直接调 `control.set` 开锁 | 拒绝并提示改用 `access.open` | 通过 |

## 7. 缺陷记录

开发过程中发现并修复的 5 个缺陷（均已回归）：

| 编号 | 现象 | 根因 | 修复 |
|---|---|---|---|
| BUG-01 | MQTT 设备发现不到，日志刷 `event handler failed: discovered` | `bus.emit` 派发事件对象，订阅方按 `{descriptor}` 解构得到 `undefined` | 订阅方改为读 `event.data.descriptor`，并在日志中带上错误文本 |
| BUG-02 | 多设备只发现最后一台 | 所有设备共用 `home/discovery` 且 retain，后写覆盖前写 | 改为 `home/discovery/<id>` 每设备一主题 |
| BUG-03 | 握手报 `unable to authenticate data`，客户端超时 | 演示进程口令与已有 `keys.json` 不一致，`hello_ack` 构造指纹时抛错 | 密钥库初始化即校验可解锁（快速失败）；握手对指纹异常降级容错 |
| BUG-04 | `system.hello` 返回 UNAUTHORIZED | API 对所有非登录方法强制校验令牌 | hello 豁免鉴权（登录前需拿指纹） |
| BUG-05 | WS 全部失败，报 `ERR_CRYPTO_INVALID_CURVE` | Node `createECDH` 不支持 x25519 | 改用 `generateKeyPairSync` + `diffieHellman`，封装 `security/x25519.mjs` |
| BUG-06 | 开发用密钥库 `.runtime/keys.json` 被误提交进 Git；同时 `.gitignore` 的 `core/` 规则误伤了 `gateway/core/` 内核源码 | 首次提交早于忽略规则；忽略规则未做根锚定 | 从索引移除并本地重建密钥库；`core/` 改为 `/core/` |

> **安全提醒：** BUG-06 涉及的开发密钥仍存在于历史提交中。**上线前必须生成全新的密钥库**（删除 `.runtime/` 后重新启动即可），不得沿用仓库历史中的任何密钥。

另记录 1 次**偶发**：全量套件曾一次耗时 108 s（正常 7 s），复跑未复现，未定位到具体用例；已记录待观察。

### 10.3 上机阶段新发现的缺陷（BUG-07 ~ BUG-13）

| 编号 | 现象 | 根因 | 修复 |
|---|---|---|---|
| BUG-07 | 构建直接失败 `00303312 Cannot find the corresponding SDK version` | `compatibleSdkVersion` 写成 `"26.0.0(26)"` | API 26 起不带括号，写 `"26.0.0"`；`DEVECO_SDK_HOME` 指向 `sdk` 根目录 |
| BUG-08 | 构建成功却提示 `No signingConfig found for product default`，产物未签名无法安装 | `app.signingConfigs` 已生成，但 `products[]` 没有引用它 | `products[].signingConfig = "default"` |
| BUG-09 | 登录卡在"密钥协商完成，正在登录…"，网关侧报 `unable to authenticate data` | `Key.getEncodedDer()` 不支持 X25519；改用 AsyKeySpec 后公钥按**大端**编码成 32 字节，而 RFC 7748 是小端 | 用 `getAsyKeySpec(X25519_PK_BN)` 取标量，`bigint ↔ 字节` 全部改小端 |
| BUG-10 | 偶发解密失败（`seq=4` 那次），重试即好 | `request()` 在 `await seal()` **之后**才读取 `this.seq`，并发请求时信封里的 seq 与 AAD 用的 seq 不一致 | 进函数先取 `const seq = this.seq + 1`，全程用局部量 |
| BUG-11 | 运行十几分钟后所有设备变"离线"，控制报"设备离线，指令未下发" | `registry.markOnline()` 在状态未变化时提前 `return`，心跳不刷新 `onlineAt`，被 15 s 一次的 `sweep()` 判定离线 | 总是刷新 `onlineAt`，仅在状态翻转时才发 `availability` 事件 |
| BUG-12 | 日志持续刷 `ignored undeclared capability temperature from sim-motion-corridor` | 仿真驱动对所有 `category==='sensor'` 的设备都写入温湿度，包括只声明了人体感应的设备 | 按设备声明的 `capabilities` 填初值与漂移，只上报声明过的能力 |
| BUG-13 | 首页标题与状态栏时间重叠；四宫格只显示上面两张卡 | `setWindowLayoutFullScreen(true)` 做沉浸式却没有预留安全区；`Grid` 只设了 `columnsTemplate` 且高度不足，第二行被裁掉 | 去掉全屏沉浸，走系统默认布局；`Grid` 补 `rowsTemplate('1fr 1fr')` |

> BUG-09、BUG-10 是典型的"只有真机才会暴露"的问题：单元测试里 Node 两端都是 RV8 小端约定，
> 不会踩到大端编码的坑；并发写 seq 的竞态在串行测试里也不会出现。
