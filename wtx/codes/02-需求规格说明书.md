## 1. 引言

### 1.1 编写目的

本文档完整定义本系统的功能性与非功能性需求，作为总体设计、编码实现、测试用例编写与验收的依据。本文档与《项目前景与范围说明》（VIS-HOME-OH-001）配套：后者界定"做什么与不做什么"，本文档界定"做到什么程度"。

**读者对象：** 指导教师、团队成员、测试人员、评审专家。

### 1.2 范围

本系统由**网关端**（OpenHarmony，部署于国产主板）与**移动端**（HarmonyOS，手机/平板）构成，V1.0 覆盖赛题要求的四大中心及配套能力：

| 功能域 | 覆盖内容 |
|---|---|
| 控制中心 | 设备接入、驱动管理、设备联动 |
| 照明中心 | 灯光远程开关、调光、人体感应与环境光联动 |
| 温湿度控制中心 | 温湿度采集展示、空调控制、多品牌兼容 |
| 智能门禁 | 远程开门、门状态监测、开锁留痕与告警 |
| 支撑能力 | 场景自动化、多端界面、三层安全、运维与仿真演示 |

**不在本文档范围：** Zigbee/BLE 直连协议栈、Matter、公网云平台、语音助手、多租户、HA 数据兼容（详见《前景与范围说明》5.2）。

## 2. 总体描述

### 2.1 产品视角

系统采用**双端协同**架构：网关端常驻执行，移动端负责交互。

```
        ┌──────────────┐           局域网 / TLS + 应用层加密
        │ HarmonyOS 手机│◀──────────────────────────────┐
        │   App (ArkTS) │                               │
        └──────────────┘                               │
                                                       ▼
   ┌───────────────────────────────────────────────────────────┐
   │              OpenHarmony 网关（国产主板）                    │
   │  ┌─────────────────────┐   ┌───────────────────────────┐  │
   │  │ 服务层 (WebSocket/  │   │  表现层 (ArkUI 触屏界面)   │  │
   │  │ HTTP API + 鉴权)    │   └─────────────┬─────────────┘  │
   │  └──────────┬──────────┘                 │                │
   │  ┌──────────▼──────────────────────────▼──────────┐      │
   │  │ 应用服务层：照明 / 温湿度 / 空调 / 门禁 / 场景    │      │
   │  └──────────────────────┬──────────────────────────┘      │
   │  ┌──────────────────────▼──────────────────────────┐      │
   │  │ 内核层：事件总线 · 状态机 · 实体/设备/区域注册表  │      │
   │  └──────────────────────┬──────────────────────────┘      │
   │  ┌──────────────────────▼──────────────────────────┐      │
   │  │ 驱动层（驱动 SPI）：MQTT / HTTP / Modbus / 红外   │      │
   │  └──────────────────────┬──────────────────────────┘      │
   └─────────────────────────┼─────────────────────────────────┘
                             │
        ┌────────────────────┼────────────────────┐
        │                    │                    │
   ┌────▼────┐        ┌──────▼──────┐      ┌──────▼──────┐
   │ 照明设备 │        │ 温湿度/空调  │      │ 门禁执行机构 │
   └─────────┘        └─────────────┘      └─────────────┘
```

**外部系统接口：**

| 系统 | 关系 | 接口 |
|---|---|---|
| MQTT Broker | 依赖（可内置） | MQTT 3.1.1 / 5.0，TCP + TLS |
| 智能设备（灯/传感器/空调/门锁） | 被控 | MQTT 主题约定 / Modbus TCP / HTTP |
| 品牌空调 | 被控 | 品牌适配器（厂商 API / 红外码库 / 网关） |
| HarmonyOS 手机 App | 客户端 | WebSocket over TLS + 应用层 AEAD 加密 |

| 用户类 | 技术水平 | 使用频率 | 主要操作 |
|---|---|---|---|
| 家庭用户 | 低 | 每日多次 | 开关灯与空调、远程开门、查看温湿度 |

### 2.4 运行环境

| 项 | 网关端 | 移动端 |
|---|---|---|
| 操作系统 | OpenHarmony 5.0 Release 及以上（API 12+） | HarmonyOS（手机/平板） |
| 硬件 | 国产主板（如 RK3568 类），≥ 2 GB RAM、≥ 8 GB 存储，带触屏或外接显示 | 主流 HarmonyOS 手机/平板 |
| 网络 | 局域网，有线或 Wi-Fi | 与网关同一局域网 |
| 开发工具 | DevEco Studio（OpenHarmony SDK） | DevEco Studio（HarmonyOS SDK） |
| 外部依赖 | MQTT Broker（可内置）、外设传感器与执行机构 | 无 |

### 2.5 设计与实现约束

1. 应用主体使用 ArkTS；协议解析、加解密、高频状态处理以 C++ 实现并经 NAPI 暴露。
2. 数据持久化仅使用 relationalStore；密钥存放于 HUKS，不以明文落盘。
3. 不依赖 D-Bus、Docker、systemd。
4. 网关端与移动端的平台差异集中在"平台能力层"封装，业务逻辑层双端共用。
5. 界面遵循 ArkUI 声明式规范，网关端横屏、移动端竖屏为主，需双向适配。
6. 交付需为可安装的 HAP 包，并附部分功能源码。

### 2.6 假设与依赖

1. 设备侧遵循约定的 MQTT 主题与载荷格式（见 5.3），或经品牌适配器转换。
2. Broker 可用且网络可达；Broker 不可用时系统进入降级模式而非崩溃。
3. 系统时间正确，否则定时任务与日志时间戳异常。
4. 网关为单实例运行，不支持多网关同时写入同一数据库。
5. 门禁执行机构可由开发板 GPIO/串口驱动；无实物时由仿真驱动替代。

## 3. 功能需求

### 3.1 设备接入与驱动管理（M1，控制中心）

| 编号 | 名称 | 优先级 | 需求描述 | 验收标准 |
|---|---|---|---|---|
| FR-1.1 | MQTT 设备自动发现 | Must | 订阅发现主题，收到设备宣告后自动创建待确认设备记录 | 设备上电后 10 s 内出现在"待添加"列表 |
| FR-1.2 | 手动添加设备 | Must | 用户选择协议（MQTT/HTTP/Modbus）并填写设备 ID、名称、类型、能力集、连接参数后完成接入 | 校验必填项与 ID 唯一性，重复 ID 给出明确提示 |
| FR-1.3 | 驱动插件注册与加载 | Must | 驱动以统一 SPI 注册（`discover`/`attach`/`set`/`parseState`/`detach`），系统启动时加载内置驱动，支持运行时启用/停用 | 新增一个驱动仅需实现 SPI 并注册，无需改动内核代码 |
| FR-1.4 | 设备信息维护 | Must | 支持修改名称、所属区域、图标、厂商、型号、备注 | 修改后 1 s 内界面与数据库同步 |
| FR-1.5 | 设备删除 | Must | 删除设备及其关联实体、历史数据与自动化引用 | 删除前二次确认；存在自动化引用时提示影响范围 |
| FR-1.6 | 断网缓存与恢复 | Must | Broker 断连期间本地操作正常执行并缓存待发指令，恢复后按序补发 | 断连 72 h 内控制、场景、定时正常；恢复后 30 s 内完成补发 |
| FR-1.7 | 在线状态检测 | Must | 通过 MQTT LWT 与心跳超时（默认 60 s）判定在线/离线 | 设备断网后 ≤ 90 s 内状态变为"离线" |
| FR-1.8 | 能力声明与校验 | Must | 设备以能力集声明可操作项，系统校验控制指令是否在能力范围内 | 下发不支持的能力时拒绝并记录原因，不发送到设备 |

### 3.2 照明中心（M2）

| 编号 | 名称 | 优先级 | 需求描述 | 验收标准 |
|---|---|---|---|---|
| FR-2.1 | 灯光远程开关 | Must | 通过手机 App 或网关界面远程控制房间灯光开/关/翻转 | 点击后界面 ≤ 500 ms 反馈"处理中"，收到确认后置终态 |
| FR-2.2 | 亮度调节 | Must | 对 `brightness` 能力设置 1–100，支持滑条连续调节 | 拖动过程节流（≤ 10 次/秒），松手发送终值 |
| FR-2.3 | 色温与颜色 | Should | 支持色温（K）与 RGB 颜色设置 | 超出设备能力范围的值被钳制并提示 |
| FR-2.4 | 人体感应自动亮灯 | Must | 人体传感器触发且环境光照低于阈值（默认 50 lux）时自动开灯，亮度按时间段配置（如夜间 10%） | 感应到人后 ≤ 1 s 内开灯；光照高于阈值时不动作 |
| FR-2.5 | 无人自动关灯 | Must | 感应区域持续无人超过设定时长（默认 120 s）后自动关灯或降亮 | 延时期间再次感应到人则重新计时 |
| FR-2.6 | 照明分组与批量控制 | Must | 按区域或自定义分组批量开关、批量调光 | 30 台灯光批量控制整体完成 ≤ 2 s |

### 3.3 温湿度控制中心（M3）

| 编号 | 名称 | 优先级 | 需求描述 | 验收标准 |
|---|---|---|---|---|
| FR-3.1 | 温湿度采集与展示 | Must | 接入温湿度传感器，实时展示各房间温度（℃）、湿度（%RH）与更新时间 | 传感器上报到界面更新 ≤ 2 s；数据超 5 min 未更新标记"陈旧" |
| FR-3.2 | 空调开关与温度设定 | Must | 远程开关空调并设定目标温度（16–30℃，步进 1℃） | 设定越界被拒绝并提示；指令结果在 3 s 内回显 |
| FR-3.3 | 空调模式与风速 | Must | 支持模式（制冷/制热/送风/除湿）、风速（自动/低/中/高）、摆风开关 | 不同品牌不支持的模式置灰并给出说明 |
| FR-3.4 | 多品牌兼容 | Must | 支持海尔、格力、美的等不同品牌空调接入，用户在同一界面以相同操作方式控制 | 至少 3 个品牌可同时接入并独立控制，互不干扰 |
| FR-3.5 | 品牌适配器机制 | Must | 以统一能力模型（`hvac_mode`/`target_temp`/`fan_speed`/`swing`）定义空调能力，品牌差异由适配器映射到厂商协议（API / 红外码库 / 通用网关） | 新增一个品牌仅需实现适配器，上层界面与场景规则零改动 |
| FR-3.6 | 温湿度联动 | Should | 温度高于/低于阈值、或湿度超限时自动开启空调/除湿，可设置生效时间段 | 阈值触发后 ≤ 3 s 内下发指令；同一规则设防抖冷却时间 |
| FR-3.7 | 温湿度历史与曲线 | Should | 按设备与时间范围查询历史数据并绘制曲线 | 查询 7 天数据（降采样至 500 点）≤ 1 s |

### 3.4 智能门禁（M4）

| 编号 | 名称 | 优先级 | 需求描述 | 验收标准 |
|---|---|---|---|---|
| FR-4.1 | 远程开门 | Must | 手机 App 远程下发开门指令，需二次确认 | 二次确认后 ≤ 1 s 下发；执行结果 3 s 内回显并提示开门成功/失败 |
| FR-4.2 | 门状态监测 | Must | 实时监测门磁状态（开/关/未关严）与门锁状态（已锁/未锁） | 状态变化 ≤ 1 s 内推送到两端界面 |
| FR-4.3 | 开锁留痕 | Must | 记录每次开锁的时间、操作人、方式（App/触屏/本地钥匙）、结果 | 记录不可篡改（仅管理员可导出），可按时间筛选 |
| FR-4.4 | 异常告警 | Must | 未授权开门、门长时间未关（默认 60 s）、强制开启时推送告警到手机端 | 告警 ≤ 3 s 内到达手机端；离线时本地声光提示并补推 |
| FR-4.5 | 自动上锁与临时权限 | Should | 支持定时自动上锁；支持为访客生成限时开门权限 | 临时权限到期自动失效；上锁失败重试并告警 |

### 3.5 场景与自动化（M5）

| 编号 | 名称 | 优先级 | 需求描述 | 验收标准 |
|---|---|---|---|---|
| FR-5.1 | 手动场景 | Must | 创建包含多个设备动作的场景（如"回家""离家""睡眠"），一键按序执行 | 场景内 10 个动作整体完成 ≤ 3 s |
| FR-5.2 | 定时任务 | Must | 按"每日/每周指定日/单次"设定执行时间 | 触发误差 ≤ 5 s；设备重启后任务不丢失 |
| FR-5.3 | 状态触发规则 | Must | 以设备状态变化为触发条件（如湿度 > 70%、门被打开），可附加时间与状态条件，执行动作 | 支持"触发—条件—动作"三要素；条件不满足时不执行 |
| FR-5.4 | 场景/规则编辑与启停 | Must | 支持新建、编辑、复制、删除、启用/停用 | 停用后不再被触发，历史执行记录保留 |
| FR-5.5 | 执行日志与失败提示 | Should | 记录每次执行的动作明细与结果，失败项高亮 | 可查看最近 100 次执行记录 |
| FR-5.6 | 冲突处理 | Should | 同一实体被多个规则同时下发时，按优先级与后到先执行原则处理 | 冲突发生时记录告警日志并在界面提示 |

### 3.6 空间与多端界面（M6）

| 编号 | 名称 | 优先级 | 需求描述 | 验收标准 |
|---|---|---|---|---|
| FR-6.1 | 区域管理 | Must | 创建/重命名/删除区域（客厅、主卧、书房等），设备归属唯一区域 | 删除区域时设备转入"未分配"，不连带删除设备 |
| FR-6.2 | 首页卡片布局 | Must | 首页按区域展示设备卡片（灯、空调、温湿度、门禁），支持排序 | 布局持久化，重启后保持 |
| FR-6.3 | HarmonyOS 手机端 App | Must | 提供 HAP 安装包，在 HarmonyOS 手机上实现远程查看与控制全部四大中心 | 手机端可完成开关灯、调空调、开门、看温湿度，且与网关状态实时同步 |
| FR-6.4 | 网关端触屏界面 | Must | 网关主板屏幕提供本地面板，断网时仍可操作 | 断网状态下本地面板可控制全部已接入设备 |
| FR-6.5 | 多尺寸与横竖屏适配 | Must | 网关横屏、手机竖屏，不同分辨率下无控件遮挡与截断 | 在 ≥ 2 种分辨率下布局正常 |
| FR-6.6 | 状态可视化与主题 | Should | 以颜色/图标/文字表达在线、离线、异常、执行中四态；支持浅色/深色主题 | 四态在两种主题下均可辨识 |

### 3.7 用户与安全（M7，三层加密）

| 编号 | 名称 | 优先级 | 需求描述 | 验收标准 |
|---|---|---|---|---|
| FR-7.1 | 本地账户与登录 | Must | 首次启动创建管理员，支持本地账户登录、密码修改 | 连续 5 次密码错误锁定 5 分钟；密码加盐哈希存储 |
| FR-7.2 | 角色权限 | Must | 管理员（全部）、成员（控制与场景）、访客（只读）；门禁开门仅管理员与授权成员可用 | 越权操作被拒绝并记录审计日志 |
| FR-7.3 | 传输层加密 | Must | 网关与手机间使用 TLS 1.2+（WebSocket over TLS）；MQTT 通道支持 TLS | 抓包仅见密文；证书校验失败时拒绝连接并提示 |
| FR-7.4 | 数据层加密 | Must | 业务载荷采用 AEAD（AES-256-GCM）端到端加密，含随机 nonce 与防重放序号 | 重放旧报文被拒绝；篡改载荷导致解密失败并记录 |
| FR-7.5 | 密钥层保护 | Must | 密钥生成、存储、使用均由 HUKS 完成，密钥不出安全区；支持密钥轮换与失效 | 数据库中无明文密钥；密钥轮换后旧密钥不可再解密新数据 |
| FR-7.6 | 审计与数据保护 | Must | 记录登录、设备增删、开门、配置变更等敏感操作；备份文件中的凭据与密钥字段加密 | 审计日志不可被普通成员删除；备份文件不可被直接解析出凭据 |

### 5.2 硬件接口

| 接口 | 用途 | 说明 |
|---|---|---|
| 触屏/显示 | 网关本地交互 | 支持横屏 |
| GPIO / 串口 | 门禁执行机构、继电器 | 用于驱动电磁锁或舵机 |

| 传感器接口 | 温湿度、人体感应、光照 | 经 MQTT 或 GPIO 接入 |

### 5.3 软件接口（MQTT 主题约定）

| 主题 | 方向 | 载荷 | 说明 |
|---|---|---|---|
| `home/discovery/<device_id>` | 设备 → 网关 | `{id, name, model, brand, category, capabilities[], areaId}` | 设备宣告（retain），每设备一个主题，避免互相覆盖 |
| `home/<device_id>/state` | 设备 → 网关 | `{capability: value, ts}` | 状态上报 |
| `home/<device_id>/set` | 网关 → 设备 | `{msg_id, capability, value}` | 控制指令 |
| `home/<device_id>/ack` | 设备 → 网关 | `{msg_id, result, error?}` | 指令确认，用于 FR-3.2、FR-4.1 |
| `home/<device_id>/availability` | 设备 → 网关 | `online` / `offline`（LWT） | 在线状态，用于 FR-1.7 |

QoS 约定：控制指令与确认使用 QoS 1；状态上报使用 QoS 0 或 1；发现与在线状态使用 QoS 1。

### 5.4 双端通信接口

| 项 | 约定 |
|---|---|
| 传输 | WebSocket over TLS 1.2+，网关监听局域网端口 |
| 发现 | mDNS 广播网关服务，或用户手动输入 IP |
| 鉴权 | 登录换取短期 Token，随请求携带，过期刷新 |
| 载荷 | JSON 报文经 AES-256-GCM 加密，携带 nonce 与序号（FR-7.4） |
| 通信模型 | 请求-响应 + 服务端主动推送（状态变更、告警） |

## 6. 数据需求

### 6.1 核心实体

| 实体 | 关键属性 | 说明 |
|---|---|---|
| Area（区域） | id、name、sort | 空间分组 |
| Device（设备） | id、name、driver_id、area_id、brand、model、online、created_at | 物理设备 |
| Entity（实体） | id、device_id、capability、current_value、updated_at | 可控制/可观测对象 |
| AcProfile（空调档案） | device_id、brand、adapter_id、capabilities[]、ir_code_set | 品牌适配配置 |
| Sensor（传感器） | id、type（temp_humi/motion/lux）、area_id、last_value、last_seen | 温湿度、人体、光照 |
| DoorLock（门禁） | id、area_id、state、lock_state、auto_lock_sec | 门禁执行机构 |
| AccessLog（开锁记录） | id、user_id、method、result、ts | 门禁留痕（不可篡改） |
| Scene（场景） | id、name、actions[]、enabled | 动作集合 |
| Automation（自动化） | id、trigger、conditions[]、actions[]、enabled | 规则 |
| User（用户） | id、name、role、password_hash、salt | 本地账户 |
| StateLog（状态历史） | id、entity_id、old、new、ts | 时序记录 |
| AuditLog（审计） | id、user_id、action、target、result、ts | 敏感操作留痕 |

### 6.2 关系

- 一个区域包含多个设备；一个设备属于至多一个区域。
- 一个设备包含多个实体；实体通过能力标识可操作项。
- 空调设备的品牌能力子集由 `AcProfile` 约束，界面据此渲染控件。
- 场景与自动化引用设备/实体；删除设备时须校验引用（FR-1.5）。

### 6.3 数据保留

| 数据 | 保留策略 |
|---|---|
| 状态历史明细 | 30 天，超期清理或降采样 |
| 开锁记录 | 永久保留，仅管理员可导出 |
| 审计日志 | 180 天 |
| 应用日志 | 7 天，按大小滚动 |
| 备份文件 | 手动管理，最多保留 5 份 |

## 7. 验收与追溯

### 7.1 验收原则

- **Must 级**需求全部通过验收测试方可判定 V1.0 完成（对应赛题"功能完整度 60 分"）。
- **Should 级**需求实现率 ≥ 80%，未实现项须在总结中说明原因。
- 每项需求对应至少一条验收测试用例（编号 `AT-<需求编号>`）。

### 7.2 关键验收场景

| 编号 | 场景 | 覆盖需求 |
|---|---|---|
| AT-01 | 新设备上电自动发现 → 确认接入 → 手机端远程开关灯 | FR-1.1、FR-2.1、FR-6.3 |
| AT-02 | 人体经过 → 暗环境自动亮灯 → 无人 2 分钟后自动熄灭 | FR-2.4、FR-2.5 |
| AT-03 | 三台不同品牌空调（海尔/格力/美的）在同一界面独立控制 | FR-3.2–FR-3.5 |
| AT-04 | 温度超过阈值自动开启空调制冷，低于阈值自动停止 | FR-3.6 |
| AT-05 | 手机端二次确认后远程开门，记录生成并可在列表中查询 | FR-4.1–FR-4.3 |
| AT-06 | 门未关超过 60 s 触发告警并推送到手机 | FR-4.4 |
| AT-07 | 断开网络后执行场景与定时，恢复后补发 | FR-1.6、NFR-3 |
| AT-08 | 三层加密验证：抓包密文、载荷解密失败拒绝重放、HUKS 中密钥不可导出 | FR-7.3–FR-7.5、NFR-9 |
| AT-09 | 无硬件条件下启用演示模式，3 分钟走完四大中心 | FR-8.4、FR-8.5 |
| AT-10 | 批量控制同一区域 30 台灯光，验证耗时 | FR-2.6、NFR-1 |
