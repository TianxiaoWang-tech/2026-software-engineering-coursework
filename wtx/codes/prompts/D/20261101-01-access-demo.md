## 意图
实现门禁的安全流程（二次确认、留痕、自动上锁、未关告警），并做一键演示脚本支撑答辩与录屏。

## 上下文（粘贴给 AI 的契约片段）
```ts
// contracts/model.d.ts（节选）
export interface AccessLogEntry { id: string; userId: string; method: 'app'|'panel'|'key'; result: 'success'|'failure'; at: number; note?: string; }
export type Role = 'admin' | 'member' | 'guest';
```

## 提示词原文
```text
【角色】你是门禁业务模块开发者。
【约束】只允许修改 gateway/domains/access/ 与 scripts/；不得绕过 ControlService 直接调驱动；
        所有失败路径（口令错、权限不足、设备离线）都必须留痕，不能只报错。
【任务】实现 access.open({deviceId,userId,role,confirm})：
        1) guest 直接拒 2) PIN 不匹配拒并留痕 3) 成功留痕 + 开门后 60s 自动上锁
        4) 门未关超过 60s 推送告警
【输出】access.mjs 完整文件。
```

## 输出与人工修改
- **采纳**：三段式校验顺序（角色 → PIN → 下发）、开门后定时上锁的定时器管理
- **修改**：AI 把"失败"只写进 `console.log` → 改为写入 `this.logs`（只追加数组），
  并在失败分支也生成 logId 返回给调用方（赛题要求"控制记录/留痕"）
- **修改**：AI 的告警只发 bus 事件 → 补 `alarm` 事件并纳入 WS 推送白名单，手机端能收到
- **补充人工设计**：直接用 `control.set` 开锁的请求，在 API 层显式拒绝并提示走 `access.open`
