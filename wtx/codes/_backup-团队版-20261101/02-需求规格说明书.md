## 1. 引言

### 1.1 编写目的

本文档定义本系统的功能性与非功能性需求，作为总体设计、编码实现、测试与验收的依据。本文档与《项目前景与范围说明》（VIS-HOME-OH-001 V1.3）配套：后者界定业务目标、特性（FE-1～FE-6）与范围边界，本文档将其细化为可验证的需求条目。

**读者对象：** 指导教师、团队成员、测试人员、评审专家。

### 1.2 范围

系统由**移动端 App**（HarmonyOS / ArkTS）与**控制网关**（国产主板，OpenHarmony）构成。控制网关经**厂商网关**接入门禁、照明、温湿度、空调四类设备，以 MQTT 统一承载属性上报与指令下发。

V1.0 覆盖 V1.2 定义的首发版本范围：

| 特性 | 覆盖内容 | 对应章节 |
|---|---|---|
| FE-1 统一控制原型 | 移动端 App 的登录、设备总览、设备详情与四类设备控制界面 | 3.6 |
| FE-2 设备接入与适配层 | 设备接入、能力注册、状态汇聚、指令转发、品牌映射 | 3.1 |
| FE-3 设备状态监控 | 四类设备属性与事件的实时展示、定时刷新与变化推送 | 3.2 |
| FE-4 设备集中控制 | 远程开关、开锁、调温等控制；事件联动 | 3.3 |
| FE-5 安全与权限控制 | 传输层加密、口令加盐哈希、身份认证、权限授权 | 3.4 |
| FE-6 运维支持 | 日志记录、异常提示、配置更新、故障排查 | 3.5 |

**不在本文档范围（V1.0）：** 历史曲线、越限告警、多设备数据对比、场景化控制、批量与定时任务、OTA 升级、远程故障诊断（均为《前景与范围说明》3.1 节所列后续版本项）；视频监控、安防报警、影音娱乐；设备私有协议逆向；硬件型号与并发指标的锁定（LI-1、LI-2、LI-3）。

### 1.3 术语与缩写

| 术语 | 说明 |
|---|---|
| **控制网关** | 本项目实现的运行于国产主板的中控程序，负责设备接入、状态汇聚与指令转发 |
| **厂商网关** | 设备厂商提供的网关，连接实际设备并对外暴露接口；本项目不改造其内部实现 |
| **能力（Capability）** | 对设备的统一抽象，由**属性（property）、事件（event）、指令（command）**三部分组成 |
| **能力注册** | 厂商网关上报设备能力描述，控制网关登记后方可管理与控制该设备 |
| **适配层** | 控制网关内屏蔽厂商协议差异的模块，将统一能力模型映射到厂商接口 |
| **指令（Command）** | 对具备控制能力的设备下发的操作，如 `lock.open`、`light.on`、`hvac.set_temp` |
| **属性（Property）** | 设备可观测的状态量，如门锁状态、开关状态、温度、湿度 |
| **事件（Event）** | 设备主动上报的瞬时发生，如开锁、人体感应、门磁变化 |
| **权限项** | 设备管理者/普通使用者之间划定的可操作范围单元（见 3.4） |
| **传输层加密** | 移动端与控制网关之间基于 TLS 的加密通道；本项目安全机制的主承载方式 |
| HAP | HarmonyOS 应用安装包格式 |
| MQTT | 轻量级发布/订阅消息协议，本项目统一承载协议 |

### 1.5 需求约定

**优先级（MoSCoW）**

| 级别 | 含义 | 处理原则 |
|---|---|---|
| Must | 必须实现 | 缺失则核心用例无法演示 |
| Should | 应当实现 | 影响体验与异常处理完整性 |
| Could | 可以实现 | 资源允许时实现 |
| Won't | 本期不做 | 明确排除（见 1.2） |

> 优先级划分依据《前景与范围说明》4.3：**Must = FE-1 至 FE-5 的核心用例 + 传输层加密、身份认证与权限授权落地；Should = FE-6 日志与异常提示。**

**编号规则**

- 功能需求：`FR-<模块号>.<序号>`，模块号与特性对应（M1↔FE-2、M2↔FE-3、M3↔FE-4、M4↔FE-5、M5↔FE-6、M6↔FE-1）
- 非功能需求：`NFR-<序号>`
- 用例：`UC-<序号>`，`UC-01～UC-07` 对应 SC-1 的七项核心用例
- 验收测试：`AT-<需求编号>`

**外部系统接口**

| 系统 | 关系 | 接口 |
|---|---|---|
| 厂商网关 | 依赖 | MQTT 3.1.1/5.0，沿用厂商既有安全策略 |
| HarmonyOS App | 客户端 | TLS 加密通道（WebSocket/HTTPS） |

| 项 | 移动端 | 控制网关 |
|---|---|---|
| 运行环境 | HarmonyOS（兼容 OpenHarmony SDK） | OpenHarmony（国产主板） |
| 开发语言 | ArkTS + ArkUI | ArkTS，性能敏感部分 C++ 经 NAPI |
| 开发工具 | DevEco Studio | DevEco Studio（OpenHarmony SDK） |
| 网络 | 与控制网关同一局域网 | 可访问厂商网关 |
| 存储 | 本地配置与缓存 | 设备档案、能力描述、日志 |

### 2.5 设计与实现约束

1. 移动端与控制网关之间**全部通信由传输层加密承载**；登录口令在此基础上单独加盐哈希处理（FE-5）。
2. 与厂商网关之间的通信**沿用厂商既有安全策略**，本项目不做二次改造。
3. 设备以统一能力模型（属性、事件、指令）描述，新增设备类型只补能力描述，**不改移动端实现**（BO-3）。
4. 数据库选型与硬件型号本期不锁定（LI-1），由实现阶段按环境确定。
5. 多品牌空调适配限于主流物联网传输协议范围，**不对私有协议逆向**（LI-3）。
6. 交付需为可安装的 HAP 及部分功能源码。

### 2.6 假设与依赖

同《前景与范围说明》2.3（AS-1～AS-3、DE-1～DE-2）。补充：

1. 厂商网关可用且已接入实际设备；不可用时系统进入降级提示而非崩溃。
2. 系统时间正确，否则日志时间戳异常。
3. 无实物硬件时，由仿真设备提供与厂商网关一致的能力描述与响应行为（AS-2）。

## 3. 功能需求

### 3.1 设备接入与适配层（M1，FE-2）

| 编号 | 名称 | 优先级 | 需求描述 | 验收标准 |
|---|---|---|---|---|
| FR-1.1 | 厂商网关接入 | Must | 配置厂商网关地址与凭据，建立 MQTT 连接并订阅其主题 | 配置正确后 10 s 内建立连接，网关在线状态可见 |
| FR-1.2 | 设备发现与接入 | Must | 接收厂商网关上报的设备清单，生成待接入设备记录 | 设备接入后 10 s 内出现在设备列表 |
| FR-1.3 | 能力注册 | Must | 解析设备能力描述（属性/事件/指令），登记到能力注册表 | 注册后该设备的属性可展示、指令可下发；缺失能力的指令被拒绝 |
| FR-1.4 | 设备信息维护 | Must | 修改设备名称、所属房间、图标、备注 | 修改后 1 s 内界面与存储同步 |
| FR-1.5 | 设备移除 | Must | 移除设备及其能力登记与状态缓存 | 移除前二次确认；移除后不再出现在列表且不再接收其数据 |
| FR-1.6 | 状态汇聚 | Must | 汇总各设备属性与事件，维护最新状态快照 | 快照与最近一次上报一致，无残留脏数据 |
| FR-1.7 | 指令转发 | Must | 将统一指令模型翻译为厂商协议并转发，跟踪执行结果 | 指令带唯一 ID，结果可在 3 s 内回执 |
| FR-1.8 | 品牌协议映射 | Must | 通过适配层将空调统一能力映射到不同品牌协议 | 至少 2 个品牌可同时接入并独立控制；新增品牌不改上层 |
| FR-1.9 | 网关异常处理 | Must | 厂商网关断连、超时、返回错误时给出明确状态与提示 | 断连后 90 s 内标记离线并提示；恢复后自动重连 |

### 3.2 设备状态监控（M2，FE-3）

| 编号 | 名称 | 优先级 | 需求描述 | 验收标准 |
|---|---|---|---|---|
| FR-2.1 | 设备总览 | Must | 按房间分组展示全部设备及其当前状态摘要 | 列表加载 ≤ 2 s；离线设备显式标记 |
| FR-2.2 | 属性实时展示 | Must | 展示门锁状态、开关状态、温湿度数值、空调运行参数等属性 | 属性变化 ≤ 2 s 内反映到界面 |
| FR-2.3 | 事件推送展示 | Must | 展示设备事件（开锁、门磁变化、人体感应等）并提示 | 事件发生 ≤ 2 s 内出现在事件列表 |
| FR-2.4 | 定时刷新与变化推送 | Must | 支持定时轮询刷新，并对支持推送的属性走变化推送 | 推送通道正常时无需轮询即可更新 |
| FR-2.5 | 数据新鲜度标识 | Should | 属性超过设定时长（默认 5 min）未更新时标记"陈旧" | 陈旧状态可见且不误导用户 |
| FR-2.6 | 能力边界提示 | Must | 当设备未暴露某属性时，界面不展示该项而非显示空值 | 未暴露项不出现占位或错误值 |
| FR-2.7 | 多设备状态一致性 | Should | 同一设备在多处展示（总览/详情）时状态保持一致 | 两处数值差异 ≤ 1 个刷新周期 |

### 3.3 设备集中控制（M3，FE-4）

| 编号 | 名称 | 优先级 | 需求描述 | 验收标准 |
|---|---|---|---|---|
| FR-3.1 | 门禁控制 | Must | 远程下发开锁指令，需二次确认 | 确认后 ≤ 1 s 下发；结果 3 s 内回显 |
| FR-3.2 | 照明控制 | Must | 灯光开/关/翻转；具备调光能力的支持亮度调节 | 点击后 ≤ 500 ms 界面反馈"处理中" |
| FR-3.3 | 空调控制 | Must | 开关、目标温度（16–30℃，步进 1℃）、模式、风速（按设备能力） | 越界值被拒绝并提示；不支持的模式置灰 |
| FR-3.4 | 指令下发与确认 | Must | 指令携带唯一 ID，等待设备确认；超时（默认 5 s）重试一次 | 重试耗尽后标记失败并提示，记录日志 |
| FR-3.5 | 控制失败提示 | Must | 控制失败时明确提示原因（离线/超时/不支持/权限不足） | 四类原因文案可区分，不出现笼统"失败" |
| FR-3.6 | 事件联动 | Must | 基于设备事件触发动作，如人体感应触发开灯 | 事件到动作下发 ≤ 2 s；规则可启停 |
| FR-3.7 | 能力校验 | Must | 下发前校验设备能力与当前状态是否允许该指令 | 不支持或不满足条件的指令不下发，给出原因 |
| FR-3.8 | 批量控制 | Could | 对同一房间多个设备批量下发同类指令 | 10 台设备批量完成 ≤ 2 s（后续版本） |

### 3.4 安全与权限控制（M4，FE-5）

| 编号 | 名称 | 优先级 | 需求描述 | 验收标准 |
|---|---|---|---|---|
| FR-4.1 | 用户登录 | Must | 账户口令登录；口令以**加盐哈希**存储，不落明文 | 数据库中无明文口令；连续 5 次失败锁定 5 min |
| FR-4.2 | 身份认证与会话 | Must | 登录成功后签发会话令牌，后续请求凭令牌鉴权，支持注销与过期 | 令牌过期后请求被拒并引导重新登录 |
| FR-4.3 | 传输层加密 | Must | 移动端与控制网关之间的全部通信经 TLS 加密通道承载 | 抓包仅见密文；证书校验失败时拒绝连接 |
| FR-4.4 | 权限授权 | Must | 按权限项对设备管理者/普通使用者授权；普通使用者仅能看到被授权设备与控制项 | 未被授权的设备在列表与详情中均不可见、不可控 |
| FR-4.5 | 越权拦截 | Must | 对越权查看/控制请求返回拒绝并记录审计 | 越权请求被拒且日志可查 |
| FR-4.6 | 登录与控制日志 | Should | 记录登录、注销、控制下发、权限变更等操作 | 可按时间与用户筛选；普通使用者不可删除 |

> **安全范围说明：** 本版安全机制以传输层加密承载通信、口令加盐哈希 + 身份认证 + 权限授权构成（《前景与范围说明》A.2）。**数据层加密与端到端密钥管理不在本期范围**，与厂商网关之间沿用厂商既有安全策略。该偏差已在《前景与范围说明》附录 B.3 标注，需在答辩中说明。

### 3.5 运维支持（M5，FE-6）

| 编号 | 名称 | 优先级 | 需求描述 | 验收标准 |
|---|---|---|---|---|
| FR-5.1 | 系统运行日志 | Should | 记录启动、连接、指令转发、异常等运行日志 | 支持按级别筛选；单次导出 ≤ 10 MB |
| FR-5.2 | 网络异常提示 | Should | 网络中断、请求超时、网关不可达时给出明确提示与重试入口 | 四类异常文案可区分 |
| FR-5.3 | 设备离线提示 | Should | 设备离线时在列表与详情显著标记，并提供最后在线时间 | 标记与时间显示正确 |
| FR-5.4 | 配置更新 | Should | 支持更新设备配置、能力描述与网关连接参数 | 更新后无需重启生效或提示需重启 |
| FR-5.5 | 故障排查 | Should | 提供连通性自检（应用↔网关、网关↔厂商网关、MQTT 状态） | 自检 5 s 内出结果并给出处置建议 |
| FR-5.6 | 在线升级 | Could | 支持应用版本检测与升级，失败可回滚 | 后续版本实现（《前景与范围说明》3.1） |

### 3.6 用户端 App 界面（M6，FE-1）

| 编号 | 名称 | 优先级 | 需求描述 | 验收标准 |
|---|---|---|---|---|
| FR-6.1 | 登录页 | Must | 账号口令登录，错误提示明确，支持记住上次账号 | 登录成功 ≤ 2 s 进入首页 |
| FR-6.2 | 设备总览页 | Must | 按房间分组展示设备卡片与状态摘要，支持进入详情 | 50 个卡片滚动流畅（≥ 30 fps） |
| FR-6.3 | 设备详情与控制页 | Must | 展示属性、事件，提供该设备支持的指令控件 | 控件与能力注册结果一致，无多余控件 |
| FR-6.4 | 四类设备页面 | Must | 门禁、照明、温湿度、空调各有适配的展示与控制布局 | 四类页面均可完成对应核心用例 |
| FR-6.5 | 响应与刷新体验 | Must | 操作有明确反馈（处理中→成功/失败），状态变化自动刷新 | 反馈 ≤ 500 ms；无需手动刷新即可见变化 |
| FR-6.6 | 双端兼容 | Must | 在 HarmonyOS 运行环境可用，兼容 OpenHarmony SDK | 至少 1 台 HarmonyOS 真机安装运行通过 |
| FR-6.7 | 界面一致性 | Should | 统一视觉规范：状态色（在线/离线/异常/处理中）、字号、间距 | 四类设备页面风格一致 |

| NFR-9 | 安全 | 传输与凭据安全 | 全部移动端↔网关通信经 TLS；口令加盐哈希存储；异常提示 4 类可区分 |
| NFR-10 | 安全 | 权限有效性 | 越权请求 100% 被拦截并留痕 |
| NFR-11 | 可扩展性 | 新增设备零改用户端 | 新增 1 类设备只在网关适配层补能力描述，用户端代码改动 = 0 行 |

## 5. 外部接口需求

### 5.1 用户界面

| 界面 | 主要元素 | 关联需求 |
|---|---|---|
| 登录页 | 账号、口令、错误提示 | FR-6.1、FR-4.1 |
| 设备总览 | 房间分组、设备卡片、状态摘要、离线标记 | FR-6.2、FR-2.1 |
| 门禁详情 | 门锁状态、开锁按钮（二次确认）、事件记录 | FR-3.1、FR-2.3 |
| 照明详情 | 开关、亮度（如有）、色温（如有） | FR-3.2 |
| 温湿度详情 | 温度、湿度、数值与更新时间 | FR-2.2、FR-2.5 |
| 空调详情 | 开关、目标温度、模式、风速（按能力） | FR-3.3 |
| 设置 | 账号、权限、网关配置、日志、自检 | FR-4.x、FR-5.x |

交互约定：所有控制操作须有"处理中 → 成功/失败"反馈；破坏性操作（移除设备、远程开锁）须二次确认。

### 5.2 硬件接口

| 接口 | 用途 | 说明 |
|---|---|---|
| 网络（Wi-Fi/以太网） | 移动端与控制网关、控制网关与厂商网关通信 | 需联网权限 |
| 存储 | 设备档案、能力描述、日志 | 需沙箱读写权限 |
| 显示与触控 | App 与网关本地界面 | 移动端为主 |

### 5.3 软件接口（MQTT，控制网关 ↔ 厂商网关）

| 主题 | 方向 | 载荷 | 说明 |
|---|---|---|---|
| `vendor/<gw_id>/devices` | 厂商网关 → 控制网关 | `{deviceId, name, room, brand, capabilities:[{type,id,range?}]}` | 设备清单与能力描述，用于 FR-1.2、FR-1.3 |
| `vendor/<gw_id>/device/<dev_id>/state` | 厂商网关 → 控制网关 | `{propertyId: value, ts}` | 属性上报，用于 FR-2.2 |
| `vendor/<gw_id>/device/<dev_id>/event` | 厂商网关 → 控制网关 | `{eventId, payload, ts}` | 事件上报，用于 FR-2.3 |
| `vendor/<gw_id>/device/<dev_id>/cmd` | 控制网关 → 厂商网关 | `{msgId, command, params}` | 指令下发，用于 FR-1.7 |
| `vendor/<gw_id>/device/<dev_id>/cmd_ack` | 厂商网关 → 控制网关 | `{msgId, result, error?}` | 指令确认，用于 FR-3.4 |
| `vendor/<gw_id>/status` | 厂商网关 → 控制网关 | `online` / `offline`（LWT） | 网关在线状态，用于 FR-1.9 |

QoS 约定：指令与确认 QoS 1；属性/事件 QoS 0 或 1；设备清单与在线状态 QoS 1。

> 主题命名以厂商网关实际规范为准；若厂商使用私有主题，由适配层映射（FR-1.8）。

### 5.4 移动端 ↔ 控制网关接口

| 项 | 约定 |
|---|---|
| 传输 | TLS 1.2+（WebSocket 或 HTTPS），全部通信经加密通道（FR-4.3） |
| 鉴权 | 登录换取会话令牌，请求携带，过期刷新（FR-4.2） |
| 主要操作 | 登录/注销、设备列表、设备详情、下发指令、事件订阅、日志查询 |
| 推送 | 服务端主动推送状态变化与事件（FR-2.4） |

### 5.5 适配层扩展接口

新增设备类型或品牌时，只需实现该接口，用户端不改动（NFR-11）：

```typescript
// 能力模型：属性 / 事件 / 指令
interface Capability {
  type: "property" | "event" | "command";
  id: string;                  // 如 'lock.state' | 'light.on' | 'hvac.set_temp'
  valueType: "bool" | "number" | "string" | "enum";
  range?: { min?: number; max?: number; step?: number; enum?: string[] };
}

// 厂商适配器：屏蔽协议差异
interface VendorAdapter {
  readonly brand: string;                 // 'haier' | 'gree' | 'midea' | ...
  readonly transport: "mqtt" | "http" | "modbus";
  capabilities(deviceId: string): Capability[];
  toVendor(deviceId: string, command: string, params: unknown): unknown;   // 统一 → 厂商
  fromVendor(deviceId: string, raw: unknown): { property?: string; value?: unknown };
  send(deviceId: string, payload: unknown): Promise<{ msgId: string }>;
}
```

## 6. 数据需求

### 6.1 核心实体

| 实体 | 关键属性 | 说明 |
|---|---|---|
| Gateway（厂商网关） | id、name、addr、online、last_seen | 设备接入的入口 |
| Device（设备） | id、name、room、brand、gateway_id、online | 四类设备之一 |
| Capability（能力） | id、device_id、type、value_type、range | 属性/事件/指令 |
| State（状态快照） | device_id、property_id、value、updated_at | 最新值，用于 FR-2.2 |
| Event（事件记录） | id、device_id、event_id、payload、ts | 用于 FR-2.3 |
| User（用户） | id、account、password_hash、salt | 口令加盐哈希（FR-4.1） |
| Permission（权限） | user_id、scope（device/property）、allowed | 权限项授权（FR-4.4） |
| Session（会话） | token、user_id、expires_at | 认证会话（FR-4.2） |
| OperationLog（操作日志） | id、user_id、action、target、result、ts | 登录与控制审计（FR-4.6） |
| SystemLog（系统日志） | id、level、module、message、ts | 运行日志（FR-5.1） |

### 6.2 关系

- 一个厂商网关接入多台设备；一台设备属于唯一厂商网关。
- 一台设备包含多个能力项；能力项决定界面控件与可下发指令（FR-3.7）。
- 用户通过权限项获得对设备/属性的可见与可控范围（FR-4.4）。
- 移除设备时须同时清理其能力、状态快照与事件记录（FR-1.5）。

### 6.3 数据保留

| 数据 | 保留策略 |
|---|---|
| 状态快照 | 仅保留最新值（V1.0 不存历史曲线） |
| 事件记录 | 30 天 |
| 操作日志 | 180 天 |
| 系统日志 | 7 天，按大小滚动 |
